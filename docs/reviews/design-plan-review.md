## Step 0

- Initial design completeness: **5/10.** The backlog names every screen and most states (empty states on the dashboard and customer page, error text on key failures), but says nothing about layout hierarchy, density, navigation, what the collector sees first, or how amounts and statuses are visually encoded. A 10 for this plan: each screen has a stated first/second/third read, every list has loading, empty, error and partial states, status badges and timeline icons are a fixed vocabulary, and the approval queue is designed as the product's hero.
- DESIGN.md: none yet. `/design-consultation` runs in Phase 5.
- Existing design reuse: none in the repository.

## Pass 1: Information architecture (4/10 → 8/10)

Fix (auto-decided): navigation is a left rail with five items in this order: **Today** (dashboard), **Approvals** (with a pending count), **Customers**, **Evaluation**, **Admin** (admin role only). The approval count is the only badge in the rail.

First reads per screen:
- Today: "What needs my attention today?" first, totals second, ageing third.
- Customer: outstanding and recommended next action first; invoices and promises second; timeline as the main column; trajectory and messages in tabs.
- Approvals: split view, queue list left, draft with guardrail report right; the three action buttons stay visible without scrolling.

## Pass 2: Interaction state coverage (5/10 → 8/10)

Fix (auto-decided): every data panel implements loading (skeleton rows), empty (sentence plus the action that fills it), error (message plus retry) and partial (some rows, a warning line). Specific copy owed by `clarify` in Phase 5. Mutations show pending on the button and never double-submit (matches eng D1).

## Pass 3: Journey and emotional arc (6/10 → 8/10)

The collector's arc is anxiety (a pile of dues) to control (a short list with reasons) to confidence (verified drafts) to relief (promise kept). Fix (auto-decided): the moments that deliver confidence and relief get visible feedback: the "matches ledger" ticks on each draft (CEO E1), and a timeline entry that highlights when a promise is fulfilled.

## Pass 4: AI slop risk (5/10 → 8/10)

Hard rejections to avoid: chat bubbles for the agent, gradient hero cards, emoji as the only status signal, sparkle icons on AI actions, cards-inside-cards dashboards. Fix (auto-decided): the brief's 🔴🟠🟡🟢 attention markers are rendered as labelled status badges with colour plus text (colour alone fails accessibility); AI actions are labelled "AI" as an actor in the timeline, not decorated.

## Pass 5: Design system alignment (not scorable yet)

No system exists; Phase 5 `design-system` creates tokens. Constraints to carry: tabular figures for all amounts, right-aligned money columns, INR lakh grouping, `05 Oct 2026` dates, one status colour scale shared by invoices, messages and promises.

## Pass 6: Responsive and accessibility (3/10 → 7/10)

The brief targets a desktop console. Fix (auto-decided): design for 1280 px and up, usable (no horizontal scroll on the page, tables scroll inside their container) down to 768 px; phone is out of scope. WCAG 2.2 AA contrast in both themes, full keyboard path through the approval queue (J/K to move, A approve, E edit, R reject, each with a visible hint), focus returns to the next item after an action.
