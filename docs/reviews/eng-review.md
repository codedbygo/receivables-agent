| # | Finding | Recommendation | Decision |
| --- | --- | --- | --- |
| A1 | API handlers, MCP tools and the orchestrator all mutate state. If each writes its own SQL, guardrails and timeline writes drift apart. | One service layer is the only code that writes. API handlers and tool functions are thin adapters over it. Timeline events and GuardrailEvents are written inside services in the same transaction as the change. | auto-decided |
| A2 | Six containers on a slow network and one laptop. | One backend image, three commands (`api`, `mcp`, `worker`). Compose still shows six services. | auto-decided |
| A3 | The orchestrator reaching tools through an MCP client adds a network hop, a second failure mode and slower tests. | One tool registry (Pydantic in/out models, typed error envelope). `MCPServer` serves it to external clients over stdio and HTTP; the orchestrator calls the same registry functions in-process with the same validation. The 4-call budget is counted in the orchestrator's registry wrapper. | auto-decided (confirms office-hours premise 3) |
| A4 | The demo clock must be the same in api, worker and mcp, and admin advances it at runtime. An env var alone cannot change at runtime across processes. | `settings` table holds `demo_today`; `DEMO_TODAY` seeds it on reset. One `clock.today()` reads it (cached per request or per run). A lint test forbids `date.today()`/`datetime.now()` for business dates elsewhere. | auto-decided |
| A5 | Job scheduling. Celery or Redis would add a service and an innovation token. | Postgres `jobs` table with `SELECT ... FOR UPDATE SKIP LOCKED`; worker loop polls every 2 s. Unique key on `(kind, run_date)` makes the daily run and promise check idempotent; send jobs keyed by message id. A tiny in-worker scheduler enqueues the daily run at 09:00 IST on the demo date. | auto-decided, ADR in Phase 3 |
| A6 | Invoice status must agree with allocations, but a CHECK cannot look across tables. | `invoice_balances` view computes paid and remaining. `status` stays a column (CHECK on the enum) and is written only by the allocation and dispute services, inside the same transaction; a service test asserts status matches the view for every invoice after the seed and after the story. | auto-decided |
| A7 | Placeholders make the model's numbers disappear from the invoice table, but the model can still write numbers in the prose. | The verifier always runs on the final assembled text, extracting from prose and table alike; placeholders reduce failures, the verifier is the guarantee. | auto-decided |
| A8 | Frontend stack. Next.js brings a server runtime and a heavy install on this network; the console is an authenticated SPA with no SEO or SSR need. | Proposed: React 19 + Vite + TanStack Query + Tailwind + a small component set, served as static files by a tiny nginx (or by FastAPI). Next.js remains the brief's default. | **open: Phase 3 checkpoint** |
| A9 | New secrets and env vars the brief did not list. | Add `BANK_WEBHOOK_SECRET` (HMAC), `MCP_TOKEN` (bearer for the HTTP transport), `SESSION_SECRET`, `CLASSIFY_MIN_CONFIDENCE`. All in `.env.example`. | auto-decided |
| A10 | Reply text reaches the model. | Classification runs with no tools at all (a pure function: text in, JSON out, validated). Only the orchestrator, after validation in code, calls `log_promise`/`log_dispute`/`escalate`. The model never sees a tool it could misuse while reading untrusted text. | auto-decided |

Production failure scenario per integration point:

| Integration | Realistic failure | Planned handling |
| --- | --- | --- |
| OpenRouter | 429 during a live demo run | backoff 3 tries, then skip customer with LLM_UPSTREAM; replay fallback in runbook |
| Mailpit SMTP | container restarted mid-send | send job fails, status `failed`, retried; idempotency key is the message id |
| Bank webhook | same event posted twice by a retrying sender | unique `event_id`; second post is a 200 no-op |
| MCP HTTP | unauthenticated client on the demo network | bearer `MCP_TOKEN`; stdio needs none |
| Postgres | not ready when api starts | `/readyz` 503; compose healthcheck ordering |
