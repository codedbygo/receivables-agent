# Test cases

Source: `docs/product/backlog.md` as of 2026-09-30 (46 stories, 161 acceptance criteria). Ids are permanent. A
retired case keeps its row with status `retired`; nothing is renumbered. The 41 ids TC-0004 to TC-0159 that tests
already cited keep their numbers and AC mapping; new ids continue from TC-0160.

Type: `unit` (no I/O), `integration` (repository or route), `e2e` (user flow), `manual` (judgement or a device).
Priority: `P1` money, auth, data loss; `P2` core flow; `P3` cosmetic. Automation: `automated` (a test function
carries the TC id in a comment), `none` (no test asserts the criterion yet), `manual-only` (a person runs it).

Oracles are tagged checks separated by `;`: `ui:` what the user sees, `data:` persisted state read back, `not:`
what must not happen, `effect:` an event, message or log line, `inv:` an invariant.

Status: `linked` means a test asserts the criterion's outcome and carries the TC id; it says nothing about whether
the test passed (no suite was run to write this table). `linked; not asserted: ...` names the part of the
criterion the linked test does not check. `untested` means no test asserts the criterion. `manual, not run` means a
person must run it and nobody has yet.

Counts: 161 cases for 161 criteria; 134 linked to a test, 20 untested,
7 manual (not run).

Not written in this pass: the risk register, scenarios, step sheets and test plan that the `test-cases` skill also
produces (`risks.md`, `test-scenarios.md`, `test-case-steps.md`, `test-plan.md`), so `cases_check.py` has not been
run against this table. Each criterion has one row; the negative and boundary rows the skill asks for are still to
be derived.
